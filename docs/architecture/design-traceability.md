deeper document only for the row being changed.

The dependency direction remains:

```text
contracts/domain ← application use cases ← ports ← adapters ← CLI or product UI
```

Filesystem discovery and coding-CLI commands are adapters. Project, skill, Component,
Flavor, identity, source-intelligence policy, and authorization values are neutral
contracts. Default product policy selects provider `none`. Workflow compilation
and generation orchestration are application services. Moving provider or filesystem
logic into a contract, or moving authorization into a skill, breaks this direction.
The shared port catalog contains only boundaries injected into a real application use
case and proven by a conforming adapter test; typed standalone services do not gain a
parallel generic protocol merely to appear hexagonal.

“Invariant boundary” means the authority relationship is stable; it does not mean every
implementation detail is fixed. The
[constraint classification decision](../decisions/0003-constraint-classification.md)
defines the terms and records the intentionally deferred guarantees.

When behavior changes, update the owning artifact, its public schema where applicable,
the high-level flow if users see a different stage, and one test at the seam plus one
end-to-end proof. Avoid documenting every class; document which authority makes each
decision and where that decision becomes observable.
